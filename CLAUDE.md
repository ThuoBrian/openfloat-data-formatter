## Project Summary

OpenFloat Data Formatter (ADF) — a Python tool that transforms Process Maker airtime disbursement exports (CSV/Excel) into the OpenFloat SaaS upload template format. The pipeline is: **Process Maker CSV → validate → normalize → map → output OpenFloat-ready .xlsx**. It also reports on the OpenFloat "Transaction Statement" exports produced *after* disbursement — successful vs unsuccessful transactions, optionally reconciled against the original input (Statement Report mode in the Streamlit app, backed by `statement.py`).

## Key Domain Rules

**Phone normalization**: strip whitespace/special chars, remove `254` or `0` prefix (only if result would be >9 digits after removal) → keep 9 digits → prepend `254` for output. Reject numbers not exactly 9 digits after stripping. Edge case: `254012345678` → strip `254` → `012345678` (already 9 digits, keep leading zero) → `254012345678`.

**Network → Account Type mapping**: `Safaricom` → `Safaricom Prepaid`, `Airtel` → `Airtel Prepaid`, `Airtel Postpaid` → `Airtel Postpaid`, `Telkom` → `Telkom Kenya Prepaid`, `Telkom Postpaid` → `Telkom Kenya Postpaid`. Unmapped networks → hard error. Mapping is case-sensitive.

**Consent**: gone. The `consent` column was dropped from the Process Maker export shape (`config.PROCESSMAKER_COLUMNS`) and from the staff template; nothing reads it and no row is ever excluded on consent. An older export that still carries the column is simply ignored. Never silently drop data — always report what was filtered and why.

**Duplicates**: same `airtime_phone` appearing more than once → warning (not auto-deduplicated).

**Amount validation**: coerce to positive number; reject ≤0 or non-numeric; warn above KES 10,000 threshold.

**Account Name / identifier column**: the `Account Name` output column is the row's identifier, verbatim — a Respondent ID, Staff ID, Case ID, or Reso ID — so a payment in OpenFloat can be traced back to its source record. **Exports name that column differently every run** (`unique_id`, `Staff ID`, `Staff`, `Respondent ID`, `respo`, `Beneficiary Ref`), so it is **detected by shape, not matched against a list** — `normalizer.py::find_account_name_column` scores each header: reject outright on an EXCLUDE token (`name`, `phone`, `amount`, `remark`, …), then canonical alias (`config.ACCOUNT_NAME_COLUMNS`) = 4, keyword + ID token = 3, keyword alone or bare `id` = 2, ID token alone = 1; highest wins, ties leftmost. **The EXCLUDE pass is load-bearing**: without it `Staff Name` beats `Staff ID`, and `case_remark` (containing the keyword `case`) wins on our own template. Resolve **once per DataFrame**, passing `frame=` so an entirely empty candidate yields to the next one that holds data, then read every row from that one column — resolving per row lets a single blank cell pull one row's Account Name from a different column than its neighbours. `Settings.account_name_column` (env `ACCOUNT_NAME_COLUMN`, set per upload by the Streamlit picker and the API's `account_name_column` form field) overrides detection; naming a column the file lacks falls back to detection with one file-level warning rather than blanking the upload. A row whose identifier cell is empty is a soft warning (row still included, Account Name empty), not a hard error. Read cells through `resolve_unique_id`, never `str(row.get(...))` — an empty pandas cell is NaN and would write the literal string `"nan"`.

**Remark / case_remark**: the `Remark` output column is built from the input `case_remark` column when present — a manually-typed reference in one of two accepted forms, both tolerating an optional space after `C#`: the **full** `C#<case_number> <project_code> RESP AIRTIME-KSH<amount> <activity_code>` (e.g. `C#37166 22505AA RESP AIRTIME-KSH29400 d05`), or the **short** `C#<case_number>` (e.g. `C# 38305`), which real exports do use. A short remark parses to `CaseRemarkParts` with `project_code`, `amount` and `activity_code` set to **None** — every reader must handle that. A short remark is **composed into the full reference** where the upload allows it (`remark.py`): project code from a project-code column (`config.PROJECT_CODE_COLUMNS`, matched on the whole header so `project_name` can never match) or else `Settings.project_code` (env `PROJECT_CODE`, the app's Project Code box); activity code from the text before `|` in `Project_Activity`; amount from the **per-case total**. Composition never touches a reference typed in full. Every composed string is round-tripped through `parse_case_remark` and only used if it comes back identical — a code containing a space would otherwise ship a reference that silently fails to parse on the statement. When any piece is missing the Remark stays short (`C#38305`) with a soft warning, never padded with invented figures. A *partially* typed full form (`C#37166 22505AA RESP`) is still a parse error, not a short remark. A well-formed value is written to the output `Remark` **in that same format**, with spacing canonicalized (`C#37166 22505AA RESP AIRTIME-KSH29400 d05`) — OpenFloat echoes Remark back in its Transaction Statement export, where `statement.py` parses it with the same `parse_case_remark`, so the output must stay parseable by that regex. Priority order: well-formed `case_remark` → raw `case_remark` text verbatim (soft warning, parse failure) → legacy `"{project_name} - {Project_Activity}"` (when `case_remark` is empty/absent). The amount embedded in a full-form `case_remark` is the per-case total, so it is cross-checked against **the total of that case's rows in this file**, not against the row's own `amount` — comparing per row warned on every row of a correctly-typed multi-row case. Soft warning; never blocks the row. The short form carries no amount, so there is nothing to cross-check. Any free-text value written to the output (Remark, Account Name) is sanitized against Excel formula injection (a leading `=`, `+`, `-`, or `@` gets a `'` prefix) before being written — see `writer.py::_sanitize_cell_value`.

**Output cell types**: `Account Number` and `Notification Phone Number` are written as Excel **numbers** (int, number_format `"0"`), matching how OpenFloat stores them — its statement export returns `254XXXXXXXXX` as an int. `writer.py::_as_phone_number` falls back to text for a value that isn't a plain digit run or that starts with `0` (possible under a non-254 `default_country_prefix`), so a leading zero is never silently dropped. `Amount` is a number; every other column is text.

**Case totals**: the amount in a composed reference sums the case's rows **in this upload**, counting only rows that pass `check_hard_errors` — a row dropped for a bad phone is not money OpenFloat is asked to send. Two consequences to leave alone: splitting one case across two uploads gives each a partial total, and the figure is per upload, not per case in Process Maker. Warnings about the whole file (no project code available, an unusable configured code, a fractional case total) are emitted **once at `row_number=1`** with `field="project_code"`, the same way a stale `ACCOUNT_NAME_COLUMN` is; only row-specific causes warn per row.

**Allowed Types**: 63 entries in the template. Note `SPA NAKURU RURAL ` has a trailing space — must be preserved verbatim.

**Statement reports**: OpenFloat Transaction Statement exports (see `sample_report_output/`) are parsed header-driven (column count varies 12–13; `Amount` always last; grand-total footer row; `Reversed` rows carry no Amount but a `Reference Id`). Classification: `Successful` (case-insensitive) = paid; **any other status is unsuccessful** and flagged for follow-up. Reconciliation against the Process Maker input matches on `normalize_phone` of `airtime_phone` vs the statement's `Account Number`, bucketing per phone: matched-paid / matched-but-unpaid / missing-from-statement / statement-not-in-input, with soft notes for amount mismatches, duplicate input phones, and multiply-paid phones. The amount embedded in a statement Remark is the **per-case total** — the rollup flag is `disbursed_total − remark_amount` per case, not a per-row comparison. A short-form (`C#<case_number>`) Remark has no amount, so that case's `remark_amount` and `difference` are `None`: the rows still group and total, there is simply nothing to compare against, and the UI shows — instead of a figure.

## Architecture

```text
src/openfloat_formatter/   # the installed Python package (hatchling, src layout)
  config.py        # Settings (Pydantic BaseSettings, env-overridable)
  models.py        # Pydantic v2 data models (OutputRow, ValidationReport, statement models)
  normalizer.py    # Phone number & amount normalization (pure functions)
  mapper.py        # Network → Account Type mapping (5-entry lookup)
  validator.py     # Input validation: phone, network, amount, duplicates
  transformer.py   # Pipeline orchestrator: read → validate → normalize → map → build output
  statement.py     # Statement Report: parse OpenFloat statements, summarize, reconcile vs input
  writer.py        # OpenFloat Excel output (openpyxl, two-sheet)
  main.py          # FastAPI app: POST /transform, /validate, /statement-report, GET /health
  ui/app.py        # Streamlit UI with two modes: Transform (upload → preview → validate →
                   #   download) and Statement Report (analyze OpenFloat statements)
tests/             # pytest suite (statement tests use synthetic workbooks only)
```

Tech stack: Python 3.11+, Pandas, OpenPyXL, FastAPI, Pydantic v2, Streamlit.

The package is installed editable via `uv sync` (pyproject + uv.lock are the single dependency source — there is no requirements.txt). Imports use `openfloat_formatter.*` everywhere; never add `sys.path`/`PYTHONPATH` hacks. The Streamlit app imports absolute (`from openfloat_formatter...`) because `streamlit run` executes it as `__main__`.

**Other directories:**

- `scripts/` — one-off/maintenance scripts, e.g. `generate_processmaker_template.py` (regenerates `docs/processmaker-input-template.xlsx`)
- `install/`, plus `run.bat`/`start.bat`/`start.sh` at the repo root — installer/launcher scripts for non-technical users (all uv-based)
- `docs/` — reference data files (table above) plus `GOTCHA.md` — development pitfalls and non-obvious behaviors; read it before debugging surprising pandas/openpyxl/template behavior
- `.github/` — GitHub metadata: `PULL_REQUEST_TEMPLATE.md`, CI workflow (ruff + mypy on Ubuntu, pytest on Ubuntu + Windows)

## Build & Run Commands

All commands run via uv (`uv sync` installs `.venv` with the package editable + dev tools; no activation or PYTHONPATH needed).

```bash
uv sync --python 3.12                        # Set up / refresh the environment
uv run pytest -v                             # Run the full test suite
uv run pytest tests/test_normalizer.py -v    # Run single test module
uv run pytest -k "test_phone" -v              # Run tests by name pattern
uv run ruff check .                           # Lint (CI runs this; config in pyproject.toml)
uv run mypy                                   # Type-check src + tests (CI runs this)
uv run uvicorn openfloat_formatter.main:app --reload   # Run FastAPI server (port 8000)
uv run streamlit run src/openfloat_formatter/ui/app.py  # Run Streamlit UI (port 8501)
uv run python scripts/generate_processmaker_template.py # Regenerate docs/processmaker-input-template.xlsx
```

## Error Handling Convention

Hard errors (invalid phone, unmapped network, invalid amount) → exclude row from output, report in validation errors. Soft warnings (duplicates, high amounts, blank `unique_id`) → include row, surface in validation warnings. The validator never mutates the DataFrame.

In statement reporting (`statement.py`), per-file structural problems (missing sheet/columns, unreadable file) never abort the whole report — they land in `StatementReport.errors` so other files still report; per-row issues (unparseable remark/date, unnormalizable account number) soft-warn.
